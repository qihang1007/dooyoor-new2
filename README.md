# DOOYOOR 㛊䎟 — 只做牛仔：官网 + 区块链溯源 + 认证二手 + 商家后台

自主牛仔品牌的**纯静态**官方网站与交易演示系统。零依赖、零外链、移动端优先。

**品牌定位**：只做牛仔。上衣、裤子、裙子、包包，四个品类全部围绕一种面料——丹宁。
**品牌配色**：靛蓝丹宁 `#1F3B63` + 铜棕缝线 `#A85A16`/`#C97A2B` + 冷中性底 `#F5F6F8`。

> 本目录是在你提供的两份初稿（`服装商城_优化版.html` 与 `admin.html`）基础上**重做并修正**的成果。
> 保留了初稿的全部业务能力，同时修掉了其中若干硬缺陷（见文末对照表）。

## 一、怎么打开

**方式一（最快）**：双击 `index.html`。全部功能可用，**不需要联网**，也不需要安装任何东西。

**方式二（推荐，尤其是要试账号与下单功能）**：起一个静态服务器，行为与线上完全一致。

- Python：`python -m http.server 8080` → 打开 `http://localhost:8080`
- Node：`npx serve .`

> **为什么要用方式二**：整个系统的账号、余额、订单、购物袋、收藏、二手商品全部保存在浏览器本地存储（localStorage）。用 `file://` 打开时，部分浏览器会**禁用或隔离**本地存储，届时会出现"换个页面登录态就没了""下单后订单查不到"等现象。起服务器不会有这个问题。另外 `file://` 下筛选状态的地址栏同步会被浏览器拒绝（已做容错，功能不受影响）。

**部署**：整个目录上传到任意静态托管即可（对象存储 / Nginx / Vercel / Netlify / GitHub Pages），无构建步骤。

## 一之二、怎么在手机上演示

有三种方式，按需要选。

### 方式 A：同一 Wi-Fi + 本地服务（推荐，功能最全）

1. **双击目录里的 `serve.bat`**。它会自动：
   - 起一个静态服务器（端口 8080）
   - 打印本机地址（`http://localhost:8080`）
   - **打印手机要访问的局域网地址**（形如 `http://192.168.1.5:8080`）
2. 手机连**同一个 Wi-Fi**（不要用流量、不要连访客网络）。
3. 手机浏览器输入脚本打印的那个 `http://192.168.x.x:8080`。

**打不开时按顺序检查**：
- **防火墙**（最常见）：首次运行会弹"是否允许访问网络"，勾选"专用网络"并允许。若当初点了取消，去 `控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙`，找到 Python 或 Node 勾上"专用"。
- **IP 选错了**：电脑若有 VMware / VirtualBox / WSL 的虚拟网卡，脚本会打印多个 IPv4。手机要用的通常是 `192.168.x.x` 或 `10.x.x.x` 那个（真实 Wi-Fi 网卡的）。
- **不在同一网段**：公司网络或访客 Wi-Fi 常做客户端隔离，设备之间互相访问不通。换成手机热点试：电脑连手机热点，再跑一次脚本。
- **手机连的是 5G 频段而电脑是 2.4G**：同一路由器下通常仍互通，但个别路由器做了频段隔离。

### 方式 B：部署到静态托管（可发给任何人、不受网络限制）

整个目录就是成品，**不需要构建**。任选其一：

| 平台 | 做法 | 适合 |
| --- | --- | --- |
| **Netlify Drop** | 打开 `app.netlify.com/drop`，把整个 `dooyoor-site` 文件夹拖进去 | 最快，几十秒出网址 |
| **Vercel** | `npx vercel` 或网页导入 | 有 CLI、方便反复更新 |
| **Cloudflare Pages** | 网页上传或连 Git 仓库 | 国内访问相对稳 |
| **腾讯云 COS / 阿里云 OSS** | 建存储桶 → 开启「静态网站」→ 上传文件 | **国内访问最快**，自有域名 |
| **Gitee Pages** | 建仓库 → 上传 → 开启 Pages | 国内、免费，但需实名 |

> 部署后朋友圈/微信里直接发网址即可，对方手机、平板、电脑都能开。
> 用国内的 COS/OSS 或 Gitee Pages 会比 Netlify/Vercel 快很多——后两者服务器在境外。

### 方式 B 之一：GitHub Pages（详细步骤）

#### 先说三个这个项目特有的点

1. **所有资源都是相对路径**（没有 `/css/...` 这类绝对路径）。所以放在 `https://用户名.github.io/仓库名/` 这样的**子路径**下也能正常工作，不需要改任何配置。
2. **GitHub Pages 服务器是 Linux，大小写敏感**。这一点本项目已机器校验过（每个 `href`/`src` 指向的文件都真实存在且大小写完全一致），所以不会出现"本地能开、线上 404"。
3. 仓库根目录有一个 `_spec/` 目录（构建规范 + 校验脚本）。GitHub Pages 默认会跑 Jekyll，而 **Jekyll 会忽略下划线开头的目录**，可能报错。因此仓库根已放了一个空的 **`.nojekyll`** 文件——**它必须一起上传，不要漏**。

#### 步骤（网页上传，不需要装 git）

1. 登录 GitHub → 右上角 `+` → **New repository**
2. 仓库名任取（例如 `dooyoor`），可见性选 **Public**（Private 仓库要用 Pages 需付费），**不要**勾选 "Add a README file"
3. 创建后进入仓库 → **Add file → Upload files**
4. 把 `dooyoor-site` **文件夹里的所有内容**（不是文件夹本身）拖进去：12 个 html、`css/`、`js/`、`assets/`、`README.md`、`serve.bat`、`AI-IMAGE-PROMPTS.md`、`_spec/`，**以及 `.nojekyll`**
   > `.nojekyll` 是隐藏文件，Windows 资源管理器默认不显示。先开"查看 → 显示 → 隐藏的项目"再用全选拖拽，否则容易漏掉。
5. 底部 **Commit changes**
6. 进入 **Settings → Pages**：Source 选 **Deploy from a branch**，Branch 选 **main**、目录选 **/ (root)**，Save
7. 等 1–2 分钟，Pages 页面顶部会显示网址：`https://用户名.github.io/dooyoor/`

#### 步骤（命令行，方便以后更新）

```bash
cd D:\deepseek\dooyoor-site
git init
git add .
git commit -m "DOOYOOR denim site"
git branch -M main
git remote add origin https://github.com/你的用户名/dooyoor.git
git push -u origin main
```

然后在 GitHub 的 **Settings → Pages** 里按上面第 6 步开启。以后每次改完只要 `git add . && git commit -m "update" && git push`，一分钟左右自动更新。

#### 三点提醒

- **演示密码会随代码公开**：`13800138000 / dooyoor`（前台）与 `admin / dooyoor2025`（后台）会出现在公开仓库里。这本来就是纯前端演示、无安全性可言，但你要知道这一点。
- **国内访问 GitHub Pages 通常偏慢**，手机 4G/5G 下可能时通时不通。要发给国内客户看，**腾讯云 COS / 阿里云 OSS 会稳得多**，而且能绑自己的域名。
- **自定义域名**：Settings → Pages → Custom domain 填你的域名，然后在域名商处按提示加一条 CNAME 记录。

### 方式 C：内网穿透（想在手机上测，但电脑和手机不在同一网络）

装 `cloudflared` 或 `ngrok`，把本地 8080 暴露成公网临时地址：

```
cloudflared tunnel --url http://localhost:8080
ngrok http 8080
```

会得到一个 `https://xxxx.trycloudflare.com` 之类的临时网址，手机直接打开。**临时地址随进程结束失效**，只适合演示。

### ⚠️ 不要用「把文件拷到手机上直接打开」

浏览器的 `file://` 协议下，**部分手机浏览器会禁用或隔离本地存储**，而本项目的账号、购物袋、订单、收藏、二手商品全部存在本地存储里。届时会出现"登录后换页就掉登录""下单后订单查不到"等现象。营销页（首页 / 商品列表 / 详情 / 品牌故事）用 `file://` 看没问题，但**账号与交易相关的必须走方式 A 或 B**。

## 四、功能清单

**浏览与选购**
- 8 个页面 + 账户中心 8 个内部视图，移动端优先（360px 起可用；≥768px 自动切桌面导航）
- 首页轮播（4 秒自动播放、可见性暂停、`prefers-reduced-motion` 时不自播、支持滑动与方向键）
- 商品列表：分类 + **成色（全新/认证二手）** + 排序 + 关键词，四者组合过滤，状态写回地址栏可直接分享
- 商品详情：3 图图库、颜色与尺码选择、数量 1–9、尺码表、手风琴说明、相关推荐
- 收藏：卡片心形一键收藏，`shop.html?fav=1` 查看，收藏二手商品也能正确跳转

**区块链溯源**
- 每件商品有唯一溯源码、交易哈希、区块高度、面料批次、工坊与全部流转记录
- `verify.html` 支持按码查证，容忍大小写、空格与全角字符；支持 `?code=` 直链
- 哈希为**确定性算法**（同一输入永远同一结果），下单时写入订单后不再变动

**交易闭环**
- 购物袋：本地持久化、数量增减、删除、优惠码（内置 `WELCOME10` 享 9 折）、满 ¥999 免运费进度条
- 结算：收集收货信息（姓名/手机号/地址）→ 校验 → 真实下单 → 扣减余额 → 写订单与流水
- 立即购买：**优先使用增值抵扣，不足部分再扣余额**
- 二手商城：先看后买，买入后余额转给卖家；卖家不存在时记入「待结算」而不是凭空消失

**账户中心**（`account.html`，`?view=` 深链）

| `overview` | 资料卡、余额卡（带演示标注）、8 宫格入口、退出登录 |

**增值抵扣是什么**

= 你买过的商品，**持有满 12 个月**后可按其实付价抵扣；**满 36 个月起**每满一年额外 +¥100。规则写在 `js/site-config.js` 的 `discountRule` 里。

**抵扣在哪里生效**：只在商品详情页点「立即购买」时自动优先使用（这与你初稿的行为一致）。购物袋结算使用优惠码。同一笔抵扣只能使用一次，用掉后会在记录里标记，不会重复抵扣。

**商家后台**（`admin.html`）

概览统计（6 项，按新品/二手严格区分）、商品管理（搜索、筛选、编辑、上下架）、发布新品（多图上传 + 客户端压缩 + 拖拽排序）、广告栏装修（与首页轮播共用同一份数据）、订单管理、用户管理（脱敏手机号 + 批量删除）、溯源记录。

## 六、商品图：现在是手绘 SVG，怎么换成 AI 生成图

**当前状态**：站内 19 张图**全部是手绘 SVG**——8 件商品是**结构准确的丹宁单品示意**（夹克有领子、门襟排扣、胸袋与下摆罗纹；牛仔裤有腰头、裤鼻、前袋、铜铆钉、赤耳缝线与缝线；裙子有腰头和贴袋；包有提手与拼接线），氛围图与面料特写是丹宁斜纹质感。**它们不是照片。**

**为什么不是照片**：构建这个站的过程只有文本读写能力，**无法生成图像**。所以我没有假装做到，而是把商品图做到了"结构可辨认"，另外给你一份可直接使用的提示词包。

**换成 AI 生成图的完整步骤在 [`AI-IMAGE-PROMPTS.md`](AI-IMAGE-PROMPTS.md)**，那里包含：
- 一段**共用风格前缀**（保证 14 张图看起来像同一个品牌）+ 通用负向提示词 + 品牌配色关键词
- **8 件商品逐个提示词**（含画幅、构图、面料特征、五金细节）
- **6 张氛围图提示词**（首屏、Lookbook、工坊、面料特写）
- 生成后**怎么替换的三步**（保存文件名 → 改 `js/site-config.js` 的 `image`/`gallery` → 改氛围图引用）

替换只需改 `js/site-config.js` 里的路径，**不需要改任何代码逻辑**。

## 七、区块链溯源：现在是演示，怎么接真链

**当前实现**：`js/site-config.js` 里每件商品的 `chain` 是本地演示数据，`js/orders.js` 的 `DY.chain.hash()` 用 FNV-1a 本地算出哈希。**没有任何网络请求，也没有连接任何真实区块链。**页面上已如实标注。

**接入真实链上数据的改动点**（只有两处）：
1. `js/verify.js`：把"在本地数组里查"换成请求你自己的后端接口。
2. `js/orders.js`：下单时的 `txHash` 改为后端返回的真实交易哈希。

**建议**：不要把链上查询做在前端（会泄露节点密钥，也无法防刷查）。正确做法是前端请求你的后端，由后端查链、缓存、限流。

## 八、中文名 `㛊䎟` 的显示风险

`㛊` = U+36CA，`䎟` = U+438F，都属 **CJK 统一表意文字扩展 A 区**。**相当一部分手机与电脑的系统字体不含这两个字形，会显示成空心方框（"豆腐块"）。**

当前处理：全站以拉丁词标 `DOOYOOR` 为第一视觉主体，`㛊䎟` 只作次级标识。即使缺字，品牌识别也不会破。

三种彻底方案：① 换用字体覆盖良好的常用字（改 `brand.nameCn` 与各页 HTML 里直接写的 `㛊䎟`）；② 把含这两个字形的字体子集化（约 2–5KB WOFF2）放进 `assets/` 用 `@font-face` 引入；③ 把中文名做成 SVG 用 `<img>` 引入。

**上线前请在真实手机上确认这两个字的显示效果。**

## 九、技术约定

- **零外链**：没有 Tailwind CDN、没有 Google Fonts、没有图标字体、没有外链图片。断网可用，国内秒开。
  - 字体用 `--font-display` / `--font-sans` 指向 Manrope / Inter，**本机装了就用，没装则回落系统几何无衬线**，不产生网络请求。
  - 图标全部内联 SVG；图片全部本地 SVG。
- **零构建**：改完保存即生效。
- **视觉集中**：所有颜色、圆角、阴影、字体在 `css/style.css` 的 `:root`；换主色只需改 `--accent` 等变量。
- **数据集中**：全部内容在 `js/site-config.js`。
- **JS 为原生 ES5**，不用模块，直接 `<script>` 引入，兼容性好。
- **无障碍**：语义化标签、跳转链接、键盘可操作、`aria-*` 状态、焦点可见、触控目标 ≥44px、`prefers-reduced-motion`、**允许双指缩放**。

## 十、相比初稿修正的问题

初稿是 2146 + 758 行的两个单文件应用，功能完整但存在若干硬缺陷。以下是本次修正的关键项：

### 必修的功能缺陷

| 初稿问题 | 现状 |
| --- | --- |
| **结算漏乘数量**：余额校验用含 `qty` 的总额，扣款却写 `balance -= item.price`，买 3 件只扣 1 件钱 | `orders.js` 全模块只有**一个扣款出口**，金额为 `subtotal - discount + shipping`，只扣一次 |
| **返回按钮无限乒乓**：`go()` 无脑入栈、`back()` 出栈后又调 `go()`，在两页之间永远弹不出去 | 取消返回栈，改用 `?view=` 深链 + 浏览器原生返回 |

| **抵扣规则与文案矛盾**：文案说"满 3 年起每年 +100"，实现是固定 `price+100` | 按文案真正实现，阈值取自 `discountRule` |
| **发布二手按名称反查订单**，同名订单会错配且可重复发布 | 改为**按单号**反查，并校验 `usedPublished` 防重复 |

| **余额明细与订单对不上**（抵扣全额覆盖时不写流水） | 补 0 元流水说明 |
| **统计口径错误**：所有已完成订单都算进"新品销售额"，二手恒为 0 | 按 `type` 严格区分 |

### 必修的安全与体验问题

| 初稿问题 | 现状 |
| --- | --- |
| **存储型 XSS**：用户输入与可被改写的 localStorage 数据未经转义直接拼 `innerHTML` | 所有插入 DOM 的文本经 `DY.escape()` |

## 十一、后续接后端的位置

1. **鉴权**：`js/auth.js` —— 把 `dooyoor.users.v1` 换成接口调用，session 换成 token；**务必在后端做权限校验**，前端登录门不是安全边界。
2. **下单与支付**：`js/orders.js` 的 `checkout` / `buyNow` / `buyUsed` —— 金额计算必须移到后端重算（前端金额可被篡改）。
3. **链上溯源**：`js/verify.js` 与 `js/orders.js` 的哈希来源。
4. **商品与库存**：`js/site-config.js` 的 `products` 改为接口拉取，字段结构保持不变即可，页面逻辑无需改动。
5. **表单提交**：`js/contact.js` 与 `js/main.js` 的订阅表单各加一次接口调用。
6. **服务端渲染（可选）**：目前商品列表由 JS 渲染；在意搜索引擎收录可把渲染逻辑搬到构建期。
